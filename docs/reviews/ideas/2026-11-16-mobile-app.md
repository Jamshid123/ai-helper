# Идея: мобильное приложение AuksionGO (Android / iOS)

_Цепочка `idea-review`, 16.11.2026. Решает владелец._

## Бриф

**1. Идея (словами владельца).** «Мне нужна аппка, какой стэк возьмём». Предварительно агент предложил Expo (React Native) + TypeScript; владелец попросил прогнать идею через цепочку.

**2. Зачем.** Быть в App Store и Google Play, присылать push-уведомления (победа, срок оплаты 10%, повторные торги, начало торгов), быстрый вход и привычный для части покупателей канал. Сайт уже удобен на телефоне и десктопе.

**3. Что есть сейчас** (в `main`):
- Сайт покупателя `apps/miniapp` (React + Vite, исторически назван miniapp): каталог, лот, вход по телефону и SMS-коду, допуск, комната торгов (SSE `/lots/:id/events`), выкуп (10% за 15 мин → код и 24 ч), повторные торги, уведомления на сайте (таблица `Notification`, `/me/notifications`). Админка `apps/admin`.
- API `apps/api` (NestJS + Fastify + Prisma + PostgreSQL + Redis): сессия покупателя на сайте — httpOnly-cookie + CSRF (`modules/auth/buyer-session.service.ts`); переходный вход Telegram с Bearer JWT; метка устройства в cookie (антифрод); ограничение частоты запросов; SMS через `SmsProvider` (`SMS_MODE` fake/disabled — провайдер не выбран); платежи через `PaymentProvider` (fake — партнёр не выбран: Uzum / Click / Payme).
- Общий пакет `packages/shared` (правила торгов, деньги, расписание).
- План мобайла от 13.11: `docs/plans/mobile-app.md` (частично устарел: Telegram Mini App, WebSocket, 30%); скилл `mobile` (`.claude/skills/mobile/SKILL.md`).
- Аккаунтов Apple Developer / Google Play нет; МЧЖ в процессе регистрации (юрист готовит оферту — документ «AuksionGO: описание продукта для оферты»).

**4. Ограничения.** Без over-engineering, один сервер. Правила торгов — только на сервере. Деньги — целые сумы. Команда — владелец и партнёр, каждый со своим AI-агентом (Claude Code, Codex). Решения из `docs/PROJECT_CONTEXT.md` §8 действуют.

**5. Вопросы к ревьюерам.**
- Стек: Expo (React Native) против обёртки сайта (Capacitor) и PWA — что лучше для пилота?
- Что входит в первую версию приложения, а что позже?
- Вход и сессия в приложении (cookie не подходит), push, лента торгов, оплата внутри приложения и правила сторов.
- Сроки и порядок работ; что можно делать до появления аккаунтов сторов, SMS и платёжного партнёра.

## Ревью (независимые, 16.11.2026)

### Продакт — ЗА С УСЛОВИЯМИ (приложение в сторах — после первых пятниц пилота)
- Боль — уведомления (пропускают начало и 15 минут на 10%), а не отсутствие иконки в сторе; сайт уже удобен на телефоне.
- Метрика: доля победителей, оплативших 10% за 15 минут; вторичные — «допуск → предложение цены», лоты с ≥ 2 активными, повторное участие через 7 дней. Приложение ликвидность не создаёт, а удерживает.
- Стек: сейчас PWA (manifest, установка на экран, web push; на iOS push — только у добавленного на экран сайта, 16.4+); потом Expo. Capacitor — самый высокий риск отказа Apple (4.2) при почти нулевой выгоде против PWA.
- Первая версия приложения: вход по SMS, каталог, лот, комната, выкуп и код выдачи, push (начало, перебили, победа, срок 10%), deep link на лот. Не входит: заявка продавца, оплата внутри, вход через Google/Apple, офлайн, онбординг.
- Тест: плашка «Добавить на экран и включить уведомления» после допуска + кнопка «Приложение — скоро, оставьте номер»; сравнить оплату 10% в срок с push и без. Успех: ≥ 30% допущенных включают push и у них выше оплата в срок; провал: < 10% и нет разницы. Срок 2–3 пятницы.
- Риски: IAP Apple для взноса (15–30%), ссылка «оплатить на сайте» вне США/ЕС запрещена; ревью как penny auction; аккаунты на МЧЖ + D-U-N-S — недели; личный аккаунт Google — закрытый тест 12 человек × 14 дней; второй клиент удваивает поддержку; план 13.11 устарел.
- Дальше при успехе: сначала Android на Expo, iOS — после заключения юриста.

### UX-дизайнер — ЗА С УСЛОВИЯМИ (без push и deep links приложение не нужно)
- Путь: каталог без входа, онбординг ≤ 1 экран → вход с автоподстановкой кода (iOS oneTimeCode, Android SMS Retriever) → оплата во внешнем окне и возврат на тот же лот → только теперь своя просьба о push, затем системная → push «Торги начались» открывает комнату → push «Вы выиграли — оплатите 10% до 14:35» открывает выкуп.
- Минусы сайта, которые приложение закрывает: на iOS нет вибрации (`navigator.vibrate`), SSE рвётся в фоне — нужен ресинк и плашка «Переподключаемся…», кнопка неактивна без связи.
- Навигация: 3 вкладки — «Торги», «Мои лоты», «Профиль»; колокольчик в шапке.
- Оплата: системное окно браузера + возврат по universal link (15 минут на 10% — жёстко).
- Capacitor: на Android терпимо, на iOS веб-жесты, хуже автоподстановка, риск 4.2; Expo даёт «настоящее приложение» дешевле.
- Тексты push с суммой: «Вашу цену перебили: 7 400 000 сум. Предложить больше?»; одна ссылка `auksion.expertly.uz/lot/<id>` в SMS и push; закрытый лот из push → итог, не ошибка.

### Риск-аналитик — ЗА С УСЛОВИЯМИ
- P0: Apple считает платный допуск цифровой услугой (IAP) или отклоняет по 5.3 как penny auction; Google — так же; anti-steering. Пока модель допуска не решена — подача вслепую.
- P1: удаление аккаунта как способ сбросить ограничения и обязательства; OTP-накрутка через API без cookie-метки; кража refresh-токена; push от нашего имени, клоны в сторах; политика конфиденциальности раскроет «сервер в Европе». P2: supply chain (Expo/EAS Update/npm).
- Условия: (1) модель допуска с юристом до App Store, аккаунты на МЧЖ, в карточке — реальный товар и оферта; (2) access 15 мин + refresh в SecureStore с ротацией, отзыв цепочки при повторе, «выйти везде»; (3) метка устройства = UUID в SecureStore в заголовке → тот же `deviceHash`, без IDFA/Android ID/фингерпринтинга; (4) удаление аккаунта при активных обязательствах — заявка, после — обезличивание, финансы и HMAC телефона остаются; (5) push с access token Expo, токен удаляется при выходе, на экране блокировки без сумм и ссылок; (6) только проверенные App/Universal Links, ссылка лишь открывает экран; (7) 2FA на Apple/Google/Expo, подпись EAS Update, lockfile, Dependabot.
- Желательно: Play Integrity / App Attest как сигнал для SMS, суточный бюджет SMS, минимальная версия, запрет скриншота экрана с кодом выдачи.

### Разработчик — ЗА С УСЛОВИЯМИ (Expo в `apps/mobile`; сначала API, потом экраны)
- Сессия: `BuyerSession` подходит; `otp/request|verify` принимают `deviceId` (UUID из SecureStore), токен — в теле ответа; guard: Bearer сначала ищется как мобильная сессия, потом как JWT Telegram (сейчас Bearer = только Telegram и `deviceHash` пустой — проверка «два аккаунта в одном лоте» пропускается); CSRF для Bearer не нужен; logout по Bearer.
- Push: таблица `PushToken`, `POST/DELETE /me/push-tokens`, `dispatchPush()` по образцу `dispatchSms()` через Expo Push API, `DeviceNotRegistered` → отзыв.
- Лента: `react-native-sse`, при возврате из фона — снимок лота. Словари ru/uz — перенести в `packages/shared`. Ссылки: `auksion://lot/<id>` + AASA и assetlinks на сайте.
- Объём: 12–16 дней (API 3–4, приложение 8–10, EAS и сторы 1–2); миграция `PushToken`, `Notification.pushSentAt`; новые зависимости только в `apps/mobile`.
- Риски: две версии React (не поднимать в корень, `node-linker=hoisted` не включать), `pnpm audit` по транзитивным RN-пакетам, Hermes + `Intl` с `timeZone` проверить на Android.
- Capacitor: 4–6 дней, но cookie `SameSite=Strict` в WebView не работает (всё равно нужен токен), push тем же объёмом на сервере, риск 4.2 — выигрыш около недели при худшем качестве.
- Первый шаг (без сторов, SMS и платёжки): мобильная сессия + push (фейковый отправитель) + словари в `shared` отдельным PR; затем каркас Expo и EAS preview для Android.

## Сводка для владельца

| Роль | Вердикт | Главное условие |
|---|---|---|
| Продакт | ЗА С УСЛОВИЯМИ | Сначала проверить спрос дешёвым PWA с push 2–3 пятницы; приложение — после, начиная с Android |
| UX-дизайнер | ЗА С УСЛОВИЯМИ | В первой версии обязательно push и deep links, иначе приложение не нужно |
| Риск-аналитик | ЗА С УСЛОВИЯМИ | До App Store — решить с юристом модель взноса; короткий токен + refresh, метка устройства без фингерпринтинга |
| Разработчик | ЗА С УСЛОВИЯМИ | Expo; сначала мобильная сессия и push в API, 12–16 дней всего |

**Согласны все:** если делать приложение — то Expo, а не обёртка сайта (Apple отклоняет «сайт в обёртке», cookie в WebView не работают, push всё равно нативный); оплата — во внешнем окне браузера, не внутри; главная ценность — push и открытие лота из push/SMS; вход через токен в защищённом хранилище, метка устройства — случайный UUID приложения; до подачи в App Store нужен ответ юриста по взносу за допуск; аккаунты сторов — на МЧЖ.

**Расходятся:**
1. Когда: продакт — сначала PWA и данные 2–3 пятниц, приложение потом; UX, риск и разработчик — Expo можно начинать сейчас (с условиями).
2. Тексты push: UX — с суммой («Вашу цену перебили: 7 400 000 сум»); риск — на экране блокировки без сумм и ссылок.
3. Сессия: риск — короткий токен (15 мин) + обновляемый с ротацией; разработчик — та же 30-дневная сессия, что на сайте (проще).

**Варианты:**
- **A. Сначала PWA, 3–5 дней.** Сайт ставится на экран телефона, push в браузере (задача из решения 15.11), плашка после допуска, кнопка «приложение — скоро». Через 2–3 пятницы — решение по Expo на данных. Плюс: дёшево, полезно сайту в любом случае. Риск: на iPhone push только после добавления на экран — часть людей не дойдёт.
- **B. PWA сейчас + Expo Android следом.** Параллельно с PWA — API для приложения (токен-сессия, push), затем Android-приложение (≈ 12–16 дней), iOS — после заключения юриста. Плюс: Android в сторе через 2–3 недели. Риск: вдвое больше поддержки при двух людях.
- **C. Expo на обе платформы сразу.** Как B, но iOS тоже собираем; подача в App Store — только после юриста. Плюс: быстрее всего к обоим сторам. Риск: работа над iOS может упереться в правила оплаты Apple.
