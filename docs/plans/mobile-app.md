# План: мобильное приложение AuksionGO (Android / iOS)

_Черновик 13.11.2026. Правила разработки — скилл `mobile`. Обновлять при изменении решений._

## Цель

Нативное приложение для тех, кто не пользуется Telegram или хочет push-уведомления и быстрый вход. Функции те же, что в Mini App, на **том же API** (`/api/v1`) — правила торгов только на сервере (требование ТЗ).

## Предпосылки (до старта мобайла)

| Что | Почему | Статус |
|---|---|---|
| Backend MVP: auth, лоты, допуск, комната (WebSocket), выкуп | Мобайл — клиент того же API | не начат |
| OpenAPI-контракт `/api/v1` | Типобезопасный клиент, общий с Mini App | будет с API |
| SMS-провайдер (Eskiz / Play Mobile и т.п.) | Вход по телефону без Telegram | **решение заказчика** |
| Платёжный партнёр + его мобильный SDK/страница оплаты | Допуск, предоплата 30%, остаток | **решение заказчика** |
| Аккаунты Apple Developer (99 $/год) и Google Play (25 $ разово) на компанию | Публикация в сторах | **заказчик** |
| Юридическая проверка правил сторов (см. риски) | Без этого возможен отказ в публикации | **заказчик + юрист** |

## Стек

- **Expo (React Native) + TypeScript**, Expo Router, TanStack Query — как в скилле `mobile`.
- Общий код из монорепо: `packages/shared` (правила, суммы, расписание), словари ru/uz, OpenAPI-клиент. Mini App и мобайл используют одни типы.
- Токены дизайна §10 (Expertly, Rubik) → тема React Native.
- Сборки и публикация — **EAS Build / Submit**; обновления JS — EAS Update (только исправления, не обход ревью сторов).
- Хранение токенов — `expo-secure-store`; push — Expo Notifications (FCM/APNs).

## Риски и открытые вопросы

1. **Правила App Store / Google Play для платежей.** Apple требует свою встроенную оплату (комиссия до 30%) для цифровых услуг; физические товары — исключение. Взнос за допуск к торгам может быть признан цифровой услугой. Нужна проверка юристом; варианты: оплата допуска через веб/Telegram, или IAP для допуска при обычной оплате товара.
2. **Политика сторов по аукционам.** Платное участие в торгах может проверяться как азартная механика. Нужно чётко показывать, что продаётся реальный товар, условия и правила возврата — и иметь их в публичной оферте.
3. **SMS-провайдер и стоимость SMS** — антиспам-лимиты на OTP (уже в скилле `security`).
4. **Хранение персональных данных** (ЗРУ-547) — отложено заказчиком, но для сторов нужна политика конфиденциальности и форма удаления аккаунта (требование Apple и Google).
5. **Sign in with Apple** обязателен, только если будет вход через Google/Facebook. При входе только по телефону — не нужен.

## Тестирование

- Unit — общие правила (`packages/shared`) уже покрыты; экраны — React Native Testing Library.
- E2E — Maestro: вход, допуск, предложение цены, выкуп; на эмуляторах Android и iOS в CI.
- Ручная проверка на реальных устройствах: дешёвый Android (производительность комнаты), iPhone SE (маленький экран), длинные строки uz.
- Перед публикацией — `ux-review` и `spec-check`.
