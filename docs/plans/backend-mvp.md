## Этапы

### 1. Каркас backend
- `apps/api`: NestJS + Fastify, конфиг на zod (без фолбэков секретов), pino с redact, `/api/v1/health` (БД + Redis), graceful shutdown.
- Prisma + миграции; схема по `PROJECT_CONTEXT.md` §3–4 (деньги `BigInt`, время `timestamptz`).
- Redis + BullMQ, outbox-таблица и воркер (`apps/api` в режиме `worker`).
- Testcontainers для integration-тестов (Postgres, Redis).
- Docker-образ API (multi-stage, non-root), сервисы `api`, `worker`, `redis` в `infra/docker-compose.prod.yml` (сети `db` + внутренняя; порт API `127.0.0.1:3400`).
- nginx-шаблон: `/api` и `/ws` → `127.0.0.1:3400` (применяется на сервере только после «да» заказчика).
- Расширить `deploy.yml`: сборка образа API, `prisma migrate deploy` перед запуском, health API.

### 2. Путь покупателя (боевой режим)
1. **Auth:** `POST /auth/telegram` — проверка `initData` (HMAC, `auth_date` ≤ 1 ч) → сессия (access JWT 15 мин + refresh с ротацией). Webhook бота с секретным заголовком: `message.contact` с `contact.user_id === from.id` → подтверждённый телефон. Принятие версии правил.
2. **Каталог:** `GET /lots`, `GET /lots/:id`, `GET /schedule` (серверное время, Asia/Tashkent).
3. **Допуск:** заказ `ADMISSION`, `PaymentProvider`, вебхук/статус, идемпотентность по `providerTxId`, один допуск на лот; поздняя оплата после закрытия → возврат.
4. **Торги:** `POST /lots/:id/bids` (идемпотентный ключ) — транзакция + `FOR UPDATE`, проверки допуска/времени/суммы/конфликта интересов/бана; монотонный `seq`. WebSocket-комната (Socket.IO + Redis adapter): события по `seq`, ресинк по `lastSeq`, счётчик «в комнате».
5. **Расписание:** задачи открытия 09:00 / закрытия 18:00 (пт, Ташкент), догоняющий sweep; закрытие ровно один раз → одно обязательство.
6. **Выкуп:** предоплата 30% (15 мин) → остаток (24 ч) → код выдачи; неоплата → следующий участник по рейтингу (свои 15 мин); очередь исчерпана → лот в следующую пятницу; невыкуп → бан 50 календарных дней с автоснятием; исключения при подтверждённом сбое.
7. **Уведомления** через бота (очередь, дедупликация): открытие торгов, перебили, победа, сроки.
8. **Mini App → API:** авторизация, реальные данные и комната по WebSocket, экраны победы/выкупа и кода выдачи; демо-режим сохраняется для стенда.
9. **Тесты:** все 16 сценариев приёмки из `testing` → `apps/api/test/acceptance/`.

### 3. Админка для пути покупателя
- Auth сотрудников: argon2id + TOTP, httpOnly-сессия + CSRF, блокировка после неудачных попыток; CLI `create-admin` (пароль из stdin).
- Разделы: Расписание, Лоты (редактирование до публикации, блокировка после открытия), Экспертиза (приёмка, акт, IMEI шифрованно), Выдача (код + сверка с актом, расхождение → спор), Ограничения (снятие только с причиной), Журнал аудита, Настройки (взнос, пункт выдачи).
- Подключить к API вместо заглушек; контракт — `apps/admin/README.md`.

### 4. Путь продавца
- «Стать продавцом»: заявка (физлицо/компания), статус в Mini App.
- Админка «Заявки продавцов»: решение (допуск / ручная проверка / запрос данных / отказ) с причиной и версией правила.
- Размещение внешних лотов — за флагом `EXTERNAL_SELLERS_ENABLED=false` (по ТЗ).
