## 1. Что строим

Площадка **английских аукционов** (цена только растёт) для Узбекистана. Торги — **в любой день и время** (решение 14.11.2026, заменяет «пятница 09:00–18:00» из ТЗ): у каждого лота своё окно `opensAt…closesAt` продолжительностью от 5 минут до 14 дней, максимум и минимум участников (меньше минимума к началу — отмена с возвратом 100%) и «ожидание следующего предложения» — N минут тишины после последнего предложения завершают торги досрочно. Предложение не выше предыдущей принятой цены (первое — старта) больше чем на 50%. На пилоте продавец — сама площадка; внешние продавцы включаются позже.

Монетизация сейчас: **допуск к торгам бесплатный** (решение 18.11.2026 — уходим от взноса как не соответствующего шариату; не больше 3 предстоящих и идущих торгов одновременно на покупателя); доход — наценка на собственный товар. Выкуп (решения 14.11 и 16.11.2026, реализовано): победитель за **15 минут** оплачивает **10%** своей цены → получает код выдачи и **24 часа**, чтобы оплатить остаток 90% (онлайн или на месте) и забрать товар по коду. Не оплатил 10% → победа аннулируется, ограничение участия **7 дней**, лот уходит на **повторные торги** (оплаченный допуск остальных переносится один раз). Не забрал после 10% → аннулирование без ограничения, судьбу 10% решают финансы вручную.

**Ждёт:** целевая модель «AuksionGO Halal» (бесплатный допуск, возвратный депозит, предоплата 30%) расходится с текущей схемой 10% — решение после заключения религиозной экспертизы (`docs/research/religious-review-brief.md`). Хранение депозита, срок получения и подтверждение личности на выдаче — на холде.

Клиент покупателя — **сайт** (`apps/miniapp`, удобен на телефоне и десктопе; ушли из Telegram 15.11.2026), вход по телефону и SMS-коду. Android/iOS (Expo) — позже на том же API.

## 2. Роли

**Покупатели и гости** — на сайте (`apps/miniapp`):

| Роль | Ключевые действия |
|---|---|
| Гость | Каталог, карточка лота (описание, фото, число участников), расписание |
| Покупатель | Вход по телефону + SMS-коду, принятие правил, оплата допуска, предложения цены, выкуп |
| Продавец (заявка) | На пилоте — только подача заявки, без публикации (экран пока на демо-данных) |

**Сотрудники** — в админке (`apps/admin`). Фиксированного списка ролей нет (решение 14.11.2026): роли **настраиваемые** — таблица `Role` с правами `{модуль: view|edit}` по модулям админки (`apps/api/src/modules/staff/permissions.ts`, в интерфейсе — `apps/admin/src/lib/rbac.ts`).

| Кто | Права |
|---|---|
| Владелец (`Staff.isOwner`) | Все модули + сотрудники и роли; назначается только командой `create-admin` |
| «Администратор» (стартовая роль) | Все модули, кроме сотрудников и ролей |
| «Оператор» (стартовая роль) | Каталог и лоты |
| Другие роли | Создаёт владелец из модулей админки: расписание, категории, товары, лоты, продавцы, приёмка, риски, участники, финансы, выдача, журнал. Функции из ТЗ (эксперт, риск-менеджер, финансист, сотрудник выдачи, поддержка) собираются так же |

Сервер проверяет права на каждом действии; меню и кнопки в админке — только UX. Изменить предложение цены или назначить победителя не может никакая роль (ТЗ).

## 4. Критичные инварианты (обязательно покрыть тестами)

1. Ставка принимается только: есть допуск, лот `LIVE`, `server_now` раньше фактического окончания лота (`closesAt` или раньше — после «ожидания следующего предложения», `effectiveEnd`), сумма ≥ `current + step` (первая ≥ `start`) и ≤ `maxNextBid`, нет конфликта интересов, нет активного ограничения.
2. Ставка пишется в транзакции с блокировкой строки лота (`SELECT … FOR UPDATE`); порядковый номер монотонный; при равных — выигрывает первая записанная.
3. Идемпотентность: повтор запроса ставки с тем же ключом, повтор вебхука оплаты, повтор закрытия лота — **без дублей**.
4. Закрытие лота выполняется ровно один раз и создаёт ровно одно обязательство оплаты.
5. Сотрудник не может изменить ставку или назначить победителя.
6. Все даты в БД — UTC; календарь и дедлайны — Asia/Tashkent; таймеры считает сервер.
7. Деньги — целые сумы (`bigint`), никакого float.
8. Полный IMEI, ФИО, документы — только для ролей с правом, каждое чтение — в аудит.
9. Лимит подъёма цены: предложение не выше предыдущей принятой цены (первое — старта) больше чем на 50% (`maxNextBid`, отказ `BID_TOO_HIGH`); автопредложение тоже поднимает цену не больше чем на 50% за ход.

## 5. Стек

Принцип: один язык (TypeScript) на всё, минимум движущихся частей, один сервер.

| Слой | Выбор | Почему |
|---|---|---|
| Монорепо | pnpm workspaces | Общие типы/валидация между API и клиентами без лишних инструментов |
| Backend | Node.js 22 LTS + **NestJS 11** + Fastify adapter (CommonJS; переход на ESM — до TypeScript 7) | Модули, guards (RBAC), DI из коробки; зрелый, легко масштабировать команду |
| ORM / миграции | **Prisma 6** (+ raw SQL для блокировок ставок) | Типобезопасность, понятные миграции |
| БД | **PostgreSQL 16** — свой контейнер в compose AuksionGO (`infra/docker-compose.prod.yml`), БД `auksion` | Транзакции, row locks, надёжность денег |
| Таймеры | Sweep в процессе API каждые 5 с под advisory-блокировкой PostgreSQL (`auctions/lifecycle.scheduler.ts`): открытие, закрытие, сроки выкупа. **BullMQ нет** — понадобится для очередей уведомлений | Проще, переживает перезапуски |
| Redis | **Redis 7** (контейнер в compose) — ограничение частоты запросов | Фиксированное окно, без очередей |
| Real-time | **SSE** поверх outbox (`modules/live`); **WebSocket нет** | События — подсказка «обновись», состояние по HTTP; проходит через nginx без правки конфига |
| Сайт покупателя | **React 19 + Vite + TypeScript**, TanStack Router/Query, ru/uz (`apps/miniapp`) | Телефон и десктоп, вход по SMS |
| Админка | React + Vite + shadcn/ui на основе шаблона shadcn-admin (отдельное приложение, отдельный домен) | Изоляция от публичного клиента, готовые таблицы/формы |
| Mobile (позже) | React Native (Expo) | Переиспользование TS-типов и API-клиента |
| Валидация контрактов | zod на входе API и в конфиге окружения; OpenAPI пока не генерируется | Один контракт для сайта, админки и мобайла |
| Тесты | Vitest (unit; для API — через SWC ради decorator metadata), интеграционные — на настоящих Postgres/Redis (в CI — service-контейнеры), Playwright (e2e) | Инварианты аукциона проверяются на реальной БД |
| Инфра | Docker Compose на одном VPS (Европа); reverse proxy — **nginx хоста** с Let's Encrypt (vhost-ы из `infra/server`), внутри контейнеров SPA — nginx (`infra/nginx`); GitHub Actions → образы по SSH (`docker save \| docker load`) → проверка здоровья → откат | Просто, быстро, без Kubernetes на пилоте |
| Наблюдаемость | pino-логи (JSON), healthchecks, Sentry (опционально) | |
| Бэкапы | **Ждёт:** резервных копий БД и фото пока нет; план — ежедневный `pg_dump` + шифрование + вынос за пределы сервера, настроить до боевого запуска | |

## 7. Безопасность (базовые требования)

- Секреты только в GitHub Secrets / `.env` на сервере (не в git); `.env.example` без значений.
- Покупатель: вход по телефону + SMS-коду, httpOnly cookie-сессия; метка устройства (не больше 3 номеров с устройства за 30 дней, два аккаунта с одного устройства не попадают в один лот). Вход по Telegram `initData` (HMAC + `auth_date`) остался от Mini App.
- Запросы платёжных систем: Click — подпись MD5 с секретом, Payme — ключ кассы (Basic) + только адреса Payme; сверка суммы и номера заказа; повторы — без двойного эффекта (`PaymentTransaction`, уникальность `provider + externalId`).
- Rate limit (Redis, фиксированное окно) на запрос и проверку SMS-кода, вход сотрудника, предложения цены, допуск, оплату и ленту торгов; CORS только на свои домены; Helmet/CSP.
- Админка: вход по телефону и паролю (argon2id, ≥ 12 символов), cookie-сессия 8 ч + CSRF, блокировка 5 попыток / 15 мин; второй фактор (TOTP) убран решением заказчика 14.11.2026 (расходится с ТЗ, риск принят). RBAC — настраиваемые роли из §2, проверка на сервере; аудит всех изменений и чтений чувствительных данных.
- Чувствительные поля (IMEI, паспортные данные) — шифрование на уровне приложения; медиа документов — приватное хранилище с подписанными ссылками.
- Сервер: SSH только по ключу, firewall (22/80/443), автообновления безопасности, Postgres/Redis не торчат наружу.
- Зависимости: lockfile, `pnpm audit`/Dependabot, сканирование секретов в CI.
