# Click и Payme: подключение

Решение 17.11.2026: подключаем обе системы, покупатель выбирает способ при каждой оплате (взнос, 10%, остаток).
Код готов до получения ключей; включается переменными окружения на сервере.

## Что отдать платёжным системам

| | Click | Payme |
|---|---|---|
| Адрес для запросов к нам | `https://auksion.expertly.uz/api/v1/payments/click` — и для Prepare, и для Complete (если просят два адреса: `…/payments/click/prepare` и `…/payments/click/complete`) | `https://auksion.expertly.uz/api/v1/payments/payme` (Endpoint URL кассы) |
| Номер заказа | `merchant_trans_id` = наш ID заказа (UUID, 36 символов) | поле счёта `order_id` (тип счёта — **одноразовый**) |
| Сумма | в сумах (`12000` / `12000.00`) | в тийинах (×100) |
| Возврат покупателя после оплаты | на страницу лота (`return_url`) | на страницу лота (`c`) |

## Что получить от них → переменные в `.env` на сервере

| Переменная | Откуда |
|---|---|
| `CLICK_SERVICE_ID`, `CLICK_MERCHANT_ID`, `CLICK_MERCHANT_USER_ID`, `CLICK_SECRET_KEY` | данные кассы Click (секретный ключ — только в `.env`) |
| `PAYME_MERCHANT_ID` | ID веб-кассы (параметры разработчика) |
| `PAYME_KEY` | ключ кассы; в песочнице — TEST_KEY |
| `PAYME_TEST_MODE=true` | только на время песочницы Payme (страница оплаты test.paycom.uz) |
| `PAYMENTS_MODE=live` | включает реальную оплату. Сейчас Deploy ставит демо-стенду `fake` — переключение делаем отдельным решением перед запуском |

Система без полного набора ключей покупателю не предлагается. Проверка адресов Payme (`185.234.113.1–15`) в production
выключиться не может; IP клиента берётся из последнего адреса `X-Forwarded-For`, который дописывает nginx хоста.

## Как устроено

- **Оплата**: сервер собирает ссылку на страницу Click (`my.click.uz/services/pay/?…&transaction_param=<заказ>`) или Payme
  (`checkout.paycom.uz/<base64(m=…;ac.order_id=…;a=…;l=…;c=…)>`), сайт переходит на неё.
- **Подтверждение** — только запросом системы к нам. Click: `Prepare` (можно ли оплатить: заказ, сумма, срок) →
  `Complete` (оплачено). Payme: `CheckPerformTransaction` → `CreateTransaction` → `PerformTransaction`.
  Каждая транзакция — строка `PaymentTransaction` (состояния 1 / 2 / −1 / −2, как у Payme); повтор запроса не создаёт
  второго эффекта.
- **Сроки**: если покупатель начал оплату до истечения срока (15 минут на 10%, окно торгов для взноса), оплата
  засчитывается, даже если банк списал деньги позже; пока такая оплата идёт (≤ 10 минут), победа не аннулируется.
- **Двойная оплата**: пока заказ оплачивается в одной системе (≤ 10 минут), другая отвечает «заказ уже оплачивается».
  Если дубль всё же прошёл — транзакция помечается `needsRefund`, Click возвращает автоматически, Payme — финансы.
- **Возвраты**: Click — `payment/reversal` автоматически (через 5 с после Complete или при выходе из лота). Ограничения
  Click: только полный возврат, только платежи текущего месяца (прошлого — лишь 1-го числа), только карта онлайн —
  иначе заказ остаётся `REFUND_PENDING` для финансов. Payme: возврат в кабинете Payme → Payme присылает
  `CancelTransaction` → заказ `REFUNDED`. Без нашего решения о возврате Payme получает отказ −31007.
- **Деньги после срока**: Click нельзя ответить ошибкой на Complete после списания — отвечаем «успешно» и сразу
  возвращаем. Payme: транзакция проводится, заказ уходит на возврат.

## Проверка в песочнице (когда будут ключи)

1. Payme: в кабинете создать веб-кассу, указать Endpoint URL и поле `order_id` (одноразовый счёт); `PAYME_KEY` = TEST_KEY,
   `PAYME_TEST_MODE=true`; пройти все тесты на test.paycom.uz. Наши тесты повторяют их сценарии:
   `apps/api/test/payments-providers.test.ts`.
2. Click: попросить тестовый сервис; оплатить взнос тестовой картой, проверить возврат при выходе из лота.
3. Один реальный платёж на минимальную сумму в каждой системе + возврат.

## Открытые вопросы

- Click: частичный возврат и возврат платежа прошлого месяца через API? `payment_id` для `reversal` — это
  `click_paydoc_id` из Complete (так сделано) — подтвердить. Тестовая среда, тариф.
- Payme: можно ли возвращать через API (`receipts.cancel`) платежи, прошедшие через страницу Payme по Merchant API? Тариф.
- Обоим: фискальный чек при схеме «10% → остаток» (чек предоплаты, затем продажи), ИКПУ для взноса за допуск,
  ставка НДС для ЯТТ. До ответа бухгалтера чеки не передаём (следующий шаг).
- Раздел «Платежи» в админке: список возвратов для финансов (особенно Payme) — следующий шаг.
