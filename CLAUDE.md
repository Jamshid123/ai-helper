# CLAUDE.md — правила работы в репозитории Auksion

Перед любой задачей (порядок важен — экономит токены, см. скилл `token-economy`):
1. `docs/STATUS.md` — где мы сейчас и следующий шаг.
2. `docs/CODEMAP.md` — где что лежит в коде.
3. Нужный раздел `docs/PROJECT_CONTEXT.md` (архитектура, инварианты, решения) и `docs/spec/tz.md` (ТЗ).
4. Нужный скилл из `.claude/skills/` (таблица ниже). Не перечитывай весь репозиторий.

## Скиллы

| Задача | Скилл |
|---|---|
| API, БД, торги, платежи, фоновые задачи | `backend` |
| Telegram Mini App и админка | `frontend` |
| Android/iOS (Expo) | `mobile` |
| Тесты любого уровня, TDD | `testing` |
| Секреты, авторизация, персональные данные, ревью безопасности | `security` |

## Принципы

- **Без over-engineering.** Модульный монолит, один сервер, ничего «на вырост» без запроса. Новая зависимость — только если без неё заметно хуже; обоснование в описании коммита.
- **Не фантазировать.** Если ТЗ молчит или противоречит — спроси пользователя, не додумывай бизнес-правила. Решённые вопросы фиксируй в `docs/PROJECT_CONTEXT.md` → «Решения».
- **Безопасность по умолчанию.** Секреты никогда не попадают в git, логи или ответы API. Отсутствие конфигурации = отказ в доступе, а не «открыто».
- **Доказательства, а не уверенность.** Перед словами «готово/работает/тесты проходят» — запусти команду и посмотри вывод.

## Процесс изменений (обязательно)

1. Работа идёт в рабочей ветке. Коммиты — Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, `test:`, `refactor:`).
2. После изменений, до пуша:
   - запусти lint, typecheck и тесты затронутых пакетов;
   - добавь запись в `CHANGELOG.md` (раздел `[Unreleased]`, формат Keep a Changelog);
   - если изменилась архитектура, стек, модули, схема БД, инфраструктура или переменные окружения — обнови `docs/PROJECT_CONTEXT.md` (и `.env.example`) в том же коммите;
   - обнови `docs/STATUS.md`, а при изменении структуры кода — `docs/CODEMAP.md`.
3. **Перед каждым пушем** покажи пользователю краткий список изменений (что, зачем, риски) и спроси: «Пушить?». Без явного «да» — не пушить.
4. `main` = прод: пуш в `main` автоматически выкатывает на сервер. В `main` пушится только после явного «да» пользователя и только с зелёными проверками.

## Чего не делать

- Не коммитить `.env`, ключи, дампы БД, реальные персональные данные (даже в тестах/фикстурах).
- Не отключать и не пропускать тесты ради зелёного CI.
- Не править ставки/победителя «руками» ни в коде, ни в админке — это запрещено ТЗ.
- Не использовать `float` для денег — только целые сумы (`bigint`).
