## [Unreleased]

### Added (14.11.2026 — Mini App ↔ API)
- Mini App работает с API внутри Telegram: вход по `initData` (сессия в памяти, повторный вход при 401), каталог и карточка лота, допуск (на тестовом запуске оплату имитирует сервер), комната торгов (опрос хода торгов каждые 3 с), предложение цены с ключом идемпотентности, автопредложение, «Напомнить о начале», «Мои допуски». В обычном браузере — прежний демо-стенд. Ошибки сервера показываются понятным текстом на ru/uz.
- API: `GET /api/v1/lots/:id/bids` — ход торгов для комнаты (новые сверху, участники — только публичным именем, флаг «мои»).
- API: флаг `DEMO_STAND` — разрешает `PAYMENTS_MODE=fake` в production только на демо-стенде; скрипт `dist/scripts/seed-demo.js` и workflow «Demo seed» — тестовые лоты (статусы меняет только расписание).
- nginx контейнера Mini App проксирует `/api/` в контейнер API (тот же origin); health-check выкладки проверяет API снаружи через `/api/v1/health`.

### Added (14.11.2026 — выкладка админки)
- Сервис `admin` в compose (`127.0.0.1:3402`, образ из `Dockerfile.spa`, фрейм запрещён), сборка и доставка в Deploy, health-check админки. vhost `auksion-admin.expertly.uz` + сертификат — шаг 4 в `bootstrap.sh` (идемпотентно, основной сайт и чужие vhost-ы не трогает).

### Added (14.11.2026 — Mini App: категории и выход)
- Вкладки категорий в Mini App — из `GET /categories` (названия ru/uz из админки), фильтр лотов по категории, пустое состояние. В демо-режиме — прежние «Телефоны» и «Путешествия · скоро».
- «Выйти и вернуть взнос» на карточке лота до начала торгов (с подтверждением); после выхода можно снова оформить допуск.

### Added (14.11.2026 — админка: экраны)
- Админка подключена к API: вход с подключением кода при первом входе (QR-код и ключ, ключ только в памяти вкладки; зависимость `uqr` — генерация QR без зависимостей, рисуем SVG сами), разделы «Категории», «Товары» (из товара — «Создать лот»), «Лоты» (публикация, правка до открытия, отмена с причиной и возвратом), «Участники» (поиск, ограничение/снятие, отмена допуска с возвратом — с причиной), «Журнал аудита». Раздел «Ограничения» вошёл в «Участников».
- Подписи полей форм связаны с полями (доступность); бизнес-отказы сервера показываются его текстом.

### Added (14.11.2026 — участники и выход из лота)
- Покупатель: `DELETE /lots/:id/admission` — выход из лота до открытия торгов с возвратом 100%, можно вернуться; после открытия — 409. Ограниченный участник не может оформить допуск (деньги не берутся).
- Админка «Участники» (роли RISK, SUPPORT): поиск по имени, телефону, Telegram ID; карточка (допуски, история ограничений); ограничить на срок и снять — только с причиной; отменить допуск до начала с возвратом — с причиной. Всё в журнал.
- Админка «Журнал аудита» (ADMIN): `GET /admin/audit` — новые сверху, имя сотрудника, фильтр по объекту.

### Added (14.11.2026 — админка: категории, товары, лоты)
- Категории каталога (таблица `Category`, миграция переносит лоты в «Телефоны»; «Путешествия» — выключена): `GET /categories` (публично, только включённые, ru/uz); админка — список, добавить, переименовать, включить/выключить, порядок. Выключенная категория скрывает свои лоты из Mini App.
- Товары (`Product`): карточка, акт проверки, инвентарный номер, себестоимость; полный IMEI шифруется, в админке — последние 4 цифры.
- Лоты из товара: черновик → публикация, правка до открытия (с участниками — только после отмены их допусков), отмена до начала с возвратом 100% участникам. Правила: шаг ≥ 100 000, старт не ниже себестоимости, на проде только пятничный слот 09:00–18:00 (на демо-стенде — любое окно в будущем), после открытия лот не меняется. Всё — в журнал аудита.
- Возвраты: `PaymentProvider.refund`, `RefundsService` (снятие допуска в транзакции под блокировкой лота, возврат у провайдера после коммита).

### Added (14.11.2026 — админка: вход сотрудников)
- API: вход сотрудников `POST /admin/auth/login` → `POST /admin/auth/mfa` → httpOnly-cookie сессии (8 ч, Secure, SameSite=Strict) + CSRF-токен; `GET /admin/me`, `POST /admin/auth/logout`. Пароль — argon2id (`@node-rs/argon2`: в Node 22 нет встроенного argon2, готовые сборки без компиляции), TOTP по RFC 6238 без библиотек, повтор кода не принимается, 5 неудач — блокировка на 15 мин, одинаковый ответ для неизвестного email и неверного пароля. Код подключается при первом входе (ключ/ссылка для приложения-аутентификатора).
- Модели `Staff`, `StaffSession` (в БД — только хэш токена), TOTP-секрет зашифрован AES-256-GCM ключом `DATA_ENCRYPTION_KEY` (генерируется на сервере при выкладке). Журнал аудита: вход, выход, блокировка, создание сотрудника.
- `dist/scripts/create-admin.js` (пароль только из stdin) и workflow «Admin create» (пароль из секрета `ADMIN_INITIAL_PASSWORD`).

### Added (14.11.2026 — обновления комнаты в реальном времени)
- API: `GET /api/v1/lots/:id/events` — поток событий лота (Server-Sent Events): принятое предложение (номер, сумма, время), открытие/закрытие, новый участник. Источник — outbox-таблица (в т.ч. автопредложения из планировщика), рассылка в памяти процесса, heartbeat 20 с, лимит 2000 потоков. Старые события не повторяются ни при старте, ни позже.
- Mini App: комната подписана на поток — чужое предложение видно примерно через 0,1 с (было до 3 с); по событию и после переподключения состояние перечитывается по HTTP; опрос остаётся страховкой (20 с при живом потоке, 3 с без него).

### Changed
- Целевая бизнес-модель «AuksionGO Halal»: возвратный депозит вместо невозвратного взноса, доход от наценки, система доверия вместо штрафов — записана в решениях; описание для экспертизы переписано под неё.
