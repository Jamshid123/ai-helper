# Экономия токенов без потери качества

Главная идея: **проект «помнит» себя в двух коротких файлах**, поэтому новая сессия не перечитывает репозиторий заново.

| Файл | Что в нём | Размер |
|---|---|---|
| `docs/STATUS.md` | Что сделано, что в работе, следующий шаг, известные проблемы | ≤ 60 строк |
| `docs/CODEMAP.md` | Карта кода: где что лежит, точки входа, ключевые файлы по модулям | ≤ 150 строк |
| `docs/PROJECT_CONTEXT.md` | Архитектура, стек, инварианты, решения | читать нужный раздел |

## Порядок получения контекста

1. `docs/STATUS.md` — целиком (он короткий).
2. `docs/CODEMAP.md` — найти нужный модуль и файлы.
3. Только нужный раздел `PROJECT_CONTEXT.md` / `tz.md` (через Grep по заголовку, затем Read с offset/limit).
4. Только нужный скилл из таблицы в `CLAUDE.md` — не грузить все.
5. Код — точечно: Grep по символу → Read нужного диапазона строк.

Не делать: `find .`/`ls -R` по всему репо, чтение целых больших файлов «на всякий случай», повторное чтение файла, который уже есть в контексте и не менялся.

## Поиск и чтение

- Grep с `glob`/`type` и `output_mode: files_with_matches`, потом `content` с `-C` по нужным файлам.
- Read больших файлов — с `offset`/`limit`.
- Не читать: `node_modules/` (кроме конкретного `.d.ts`, когда нужен тип библиотеки), `dist/`, `build/`, `coverage/`, `pnpm-lock.yaml` (искать в нём Grep-ом), сгенерированный Prisma client, миграции целиком (только последнюю нужную).
- Широкий обзор многих мест (> ~5 файлов, неизвестно где искать) — один подагент `Explore` с чётким вопросом; в основной контекст приходит только вывод.
- Независимые чтения и поиски — параллельно в одном шаге.

## Короткий вывод команд

- Тесты: сначала только затронутые (`pnpm -F api test -- path/to/file`), в конце — полный прогон. Репортер `--reporter=dot`; при падении — перезапуск одного теста с подробным выводом.
- Логи и длинный вывод: `| tail -n 50`, `grep -E "error|fail"`; `--silent` у pnpm, `-q` у git.
- Сборка/линт: смотреть exit code и ошибки, не весь лог.
- **Но:** проверку перед «готово» (скилл `testing`) не сокращать — полный прогон обязателен, сокращается только печать.

## Правки

- Точечные `Edit`, а не переписывание файла целиком.
- Не перечитывать файл после `Edit` для проверки — инструмент сообщит об ошибке.
- Мелкие механические замены по многим файлам — один скрипт/`sed`, а не десятки Edit.

## Ответы пользователю

- Кратко: что сделано, что проверено (с фактами), что дальше, вопросы. Без пересказа кода и логов.

## Поддержание памяти проекта (обязательно)

В конце каждой задачи, в том же коммите:
- **`docs/STATUS.md`** — обновить «Сделано / В работе / Следующий шаг / Проблемы». Старое сжимать: история живёт в `CHANGELOG.md` и git, а не в STATUS.
- **`docs/CODEMAP.md`** — если добавлены/перемещены/удалены модули, точки входа, важные файлы, скрипты, env-переменные.
- Не дублировать: CODEMAP — «где», PROJECT_CONTEXT — «как и почему», CHANGELOG — «что изменилось», STATUS — «где мы сейчас».

Если CODEMAP расходится с кодом — исправь CODEMAP, прежде чем на него опираться.
