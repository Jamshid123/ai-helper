# Testing

Основано на практиках TDD и «verification before completion» (obra/superpowers, MIT) и property-based testing — адаптировано под проект.

## Два железных правила

1. **Сначала падающий тест.** Для фичи или бага: напиши тест → запусти → убедись, что он падает *по правильной причине* → минимальный код → зелёный → рефакторинг. Тест, который сразу зелёный, ничего не проверяет.
2. **Нет доказательств — нет «готово».** Перед словами «работает», «тесты проходят», «исправлено» — запусти полную команду в этом же шаге и прочитай вывод (число тестов, exit code). «Должно работать» — не статус.

Исключения (конфиги, сгенерированный код, прототип) — только по согласованию с пользователем.

## Пирамида

| Уровень | Инструмент | Что проверяем |
|---|---|---|
| Unit | Vitest | Чистые функции: правила ставки, расчёт 30%, календарь Ташкента, переходы статусов, `formatSum` |
| Integration | Vitest + **Testcontainers** (реальные PostgreSQL и Redis) | Сервисы с БД: ставки под конкуренцией, идемпотентность, закрытие лота, вебхуки платежей, баны |
| API/contract | Supertest по Nest-приложению | Авторизация, роли, коды ошибок, отсутствие лишних полей в ответах |
| E2E | Playwright | Mini App (с моком Telegram-окружения) и админка: ключевые пути пользователя |

Не мокать БД в тестах логики ставок и платежей — блокировки и уникальные индексы работают только на настоящем Postgres.

## Обязательные инструменты

- **Fake clock**: сервис `Clock` инжектируется; в тестах — `FakeClock.set('2026-11-20T12:59:59Z')`. Не использовать реальное время в логике.
- **Фабрики данных** (`test/factories`) — без реальных телефонов/ФИО/IMEI. Телефоны вида `+998900000001`.
- **FakePaymentProvider** — умеет: успех, отказ, повторный вебхук, задержку, неверную подпись, неверную сумму.

## Тест конкуренции ставок (шаблон)

```ts
it('из двух одинаковых одновременных ставок принимается ровно одна', async () => {
  const lot = await factories.liveLot({ startPrice: 2_000_000n, step: 100_000n });
  const [a, b] = await factories.admittedUsers(lot, 2);
  const results = await Promise.allSettled([
    bids.placeBid(a.id, lot.id, 2_000_000n, randomUUID()),
    bids.placeBid(b.id, lot.id, 2_000_000n, randomUUID()),
  ]);
  expect(results.filter(r => r.status === 'fulfilled')).toHaveLength(1);
  expect(await db.bid.count({ where: { lotId: lot.id } })).toBe(1);
});
```

Для инвариантов денег/цены полезны property-based тесты (`fast-check`): «текущая цена монотонно растёт», «seq без пропусков», «сумма предоплаты + остаток = цена».

## Сценарии приёмки из ТЗ (каждый — автотест)

Источник: `docs/spec/tz.md` → «Сценарии приёмки». Держать в `apps/api/test/acceptance/` по одному файлу на сценарий:

1. Гость видит расписание и стартовую цену.
2. Оплативший допуск получает ровно один допуск (в т.ч. при повторном вебхуке).
3. Пользователь без допуска не может поставить.
4. Продавец своего лота не может поставить.
5. Одновременные одинаковые ставки → принимается одна.
6. Повтор запроса ставки с тем же ключом → тот же результат, без дубля.
7. Повтор подтверждения оплаты → без дубля допуска/возврата.
8. Перезапуск закрытия → одно обязательство.
9. Ставка в 18:00:00 (Ташкент) отклоняется; в 17:59:59 — принимается.
10. Победителю показывается 30% и таймер 15 мин.
11. Нет предоплаты → следующий участник по рейтингу ставок, отдельные 15 мин, без переторжки.
12. Предоплата засчитывается в цену; остаток и выдача в течение 24 ч.
13. Невыкуп → бан ставок на 50 календарных дней, автоматическое снятие.
14. Подтверждённый сбой / принятая жалоба → без санкции.
15. Несоответствие товара акту блокирует выдачу и запускает спор.
16. Очередь исчерпана → лот уходит в следующий пятничный слот.

## E2E (Playwright)

- Mini App: открыть каталог → карточка → оплатить допуск (fake provider) → комната → ставка → увидеть себя лидером; второй браузерный контекст перебивает ставку → первый видит обновление.
- Админка: вход с TOTP → создать лот → акт эксперта → публикация; выдача по коду.
- Запуск: `pnpm e2e -- --trace off` (trace включать только для отладки упавшего теста).

## Перед коммитом

- [ ] Новый код начинался с падающего теста.
- [ ] `pnpm test` (и `pnpm e2e` для затронутых сценариев) — вывод показан, 0 упавших.
- [ ] Ни один тест не пропущен (`.skip`, `.only`) и не ослаблен ради зелёного.
